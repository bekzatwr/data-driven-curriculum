# Frontend (Дамир) — `web/`

React 19 + TypeScript + Vite. Все P0-экраны подключены к реальному API ветки `integration/p0-server`:

| Шаг | Маршрут | API |
| --- | --- | --- |
| 1. Данные | `/` | `POST /api/datasets/demo`, `POST /api/datasets/import?dry_run=true\|false`, `GET /api/datasets`, шаблоны CSV |
| 2. Обзор | `/datasets/:id/overview` | `GET /filters`, `GET /overview`, `GET /topics/:topic_id` |
| 3. Сравнение | `/datasets/:id/comparison` | `GET /comparison` |
| 4. План часов | `/datasets/:id/plan?class=7A` | `POST /plans/preview`, `POST /plans` |
| 5. Отчёт | `/plans/:plan_id`, `/reports` | `GET /api/plans/:id`, `GET /api/plans/:id/export.csv` |

## Запуск в разработке

```bash
# терминал 1 — сервер (из корня репозитория)
python scripts/start.py --dev

# терминал 2 — интерфейс
cd web
npm ci
npm run dev
```

Открыть http://localhost:5173. Vite проксирует `/api` на `http://127.0.0.1:8000` (другой адрес — `VITE_API_PROXY`). Для отдельного API-домена при сборке задайте `VITE_API_BASE_URL`.

## Сборка и единый сервер

```bash
cd web && npm ci && npm run build      # → web/dist
cd .. && WEB_DIST_DIR=web/dist python -m uvicorn backend.app.main:app --port 8000
```

FastAPI раздаёт `web/dist` и SPA-fallback для глубоких ссылок (`/plans/<id>` и т. п.). В Docker: `docker build --build-arg APP_TARGET=fullstack .`

## Что реализовано по ТЗ

- Каждый экран: загрузка (скелетоны), успех, пустая выборка, ошибка с кнопкой «Повторить». При смене фильтров старые данные приглушаются с плашкой «Обновляем…», чтобы не выглядеть новым результатом.
- `null` → «Нет данных», никогда не 0. Проценты с одним знаком, разницы в «п.п.», даты в UTC+5.
- Фильтры классов/учебников/версии общие для обзора и сравнения (сохраняются при переходе).
- Импорт: «Импортировать» доступно только после успешной проверки тех же файлов и параметров; ошибки — таблица «файл / строка / поле / причина».
- Обзор: KPI, теплокарта «тема × класс» (дивергентная шкала вокруг порога), таблица с сортировкой, панель темы с переходом к сравнению.
- Сравнение: статус сопоставимости с конкретными причинами, разница приростов только при `comparable`, без «лучшего учебника».
- План: явный выбор одного класса, редактирование min/max/важности/блокировки (расчёт помечается устаревшим), ручная правка часов с клиентской проверкой суммы, границ, блокировок и ±лимита; «Сохранить» активна только при выполнении ограничений.
- Отчёт: из сохранённого снимка, CSV, JSON, печать (элементы управления скрыты), отметка об искусственных данных.
- Светлая/тёмная тема, адаптив до 375 px (таблицы с горизонтальной прокруткой), основной размер 1366×768.
