# Передача общего сервера команде

В `analytics/toni` объединены backend Бекзата `f274142`, планировщик Айданы и аналитика Тони. `python scripts/start.py` запускает весь сервер; `/docs` и `/openapi.json` описывают работающие маршруты. Ручной интеграционный патч не нужен. Подробности — [P0_INTEGRATION.md](P0_INTEGRATION.md). Фронтенд ещё не включён; P1 остаётся после общего P0.

Для тестов создайте общее окружение через `python scripts/start.py --dev --install-only` и используйте Python из `.venv`; зависимости — `requirements-dev.txt`. Интеграция находится в ветке Тони и не означает автоматического слияния в `main` или изменения чужих веток. Проверку и объединение PR выполнять по правилам README.

## Дамир — фронтенд

- Базовый URL локально — `http://127.0.0.1:8000`; Origins localhost/127.0.0.1:5173 уже разрешены.
- Импорт: multipart `dry_run=true` → показать `counts`, `preview`, `warnings` → подтверждённый `dry_run=false` → сохранить фактический `dataset_id`. HTTP 200 при повторе — успех.
- Демо: `POST /api/datasets/demo` → `/api/datasets/{id}/filters`. Генератор `analytics.demo` един для общего сервера и CSV Тони. Показывать маркировку при `source_type=demo`/`is_demo=true`.
- Аналитика: `/api/datasets/{id}/overview`, `/topics/{topic_id}`, `/comparison`. Поля, параметры и единицы описаны в [TONI.md](TONI.md). Массивы классов/учебников передавать повторяющимися query-параметрами.
- `/api/capabilities` сообщает `analytics=true`, `textbook_comparison=true` и доступность планов. Импорт/restore отключены в публичном деморежиме; ограничения файлов и строк брать из этого ответа.
- План строится для одного `class_id`. После сохранения открыть `/api/plans/{plan_id}`; печать и CSV должны соответствовать сохранённому снимку, а не текущему экрану аналитики. Все элементы отчёта и кнопки печати реализует фронтенд.
- Для ошибок использовать `code`, `message`, `details`, `total_errors`. `null` показывать как отсутствие данных, сохраняя отличие от результата 0.
- `/api/datasets/{id}/quality` описывает полноту записей. `paired_post_share` — доля 0–1, не процент всех учеников школы; это не замена аналитике Тони.
- Перенос набора: GET `/api/datasets/{id}/package`, затем POST `/api/datasets/restore?dry_run=true` с полным JSON; после подтверждения повторить с `false`. Восстановленное демо получает `source_type=upload`.
- Готовую сборку можно раздавать тем же сервером через `WEB_DIST_DIR=web/dist`.

JSON-примеры в `contracts/` используют условные ID. ID набора, темы и плана всегда брать из ответа API. HTTP `/results` имеет пагинацию, `total`, `limit`, `offset`; аналитические маршруты уже считают полный набор на сервере.

## Тони — аналитика и демоданные

Реализация находится в `analytics/`: чистые расчёты `topics.py`/`comparison.py`, адаптер `api.py`, схемы `models.py`, генератор `demo.py`. Роутер и `AnalyticsError` включены в стандартный `create_app()` без дублирования. Дополнительная фабрика `analytics.app:create_integrated_app` остаётся совместимой.

`Store.load_results` возвращает до 10 000 валидированных строк целиком; `get_dataset` проверяет видимость до вычислений. `get_topics` задаёт порядок и названия тем. Нулевые баллы сохраняются, отсутствие пары не превращается в нулевой прирост; версии и шкалы не объединяются автоматически.

`analytics.demo.demo_files()` — основной генератор: 120 учеников, четыре класса, шесть тем, 1440 строк, 24 часа. Для `equations` разность приростов A−B равна 8 п.п. После изменения демоданных контрольная сумма создаёт отдельный набор, сохраняя предыдущие планы.

Дальнейшие изменения API сопровождаются тестами и регенерацией `contracts`. Паспорт `/quality` считает структурную полноту; JSON-пакет переносит исходные данные, не рассчитанные показатели.

## Айдана — планы и отчёты

Действующие файлы — `planner/rules.py`, `planner/service.py`, `planner/api.py`, `planner/storage.py`, `planner/contracts.py`. Планировщик включён в общий запуск и сохраняет P0-снимки в `aidana_plan_snapshots` в той же SQLite, что и наборы. Подготовленная таблица `plans` не является хранилищем этих действующих снимков.

Снимок содержит источник, класс, итоговые показатели, настройки, ограничения, часы, объяснения и признак ручной правки. Он не хранит полный экран сравнения двух учебников. Сервер повторно проверяет сумму, границы, блокировки и лимит изменения; исходный набор остаётся неизменяемым. Ограничение полей часов — 10 000, даже если импорт допускает больше.

## Граница P1

Таблица `plan_reviews`, схема `PlanReviewInput` и `validate_review_structure` подготовлены в backend, но маршруты и вычисления повторного теста не включены. Это не готовый модуль проверки эффекта плана. При будущей реализации понадобятся подтверждение соответствия ID, совместимость тестов и последовательность дат `baseline ≤ started_on ≤ completed_on ≤ followup`, парная динамика и сохранённый снимок. До готовности общего P0 эту часть не расширяем.

## Проверка и передача капитану

- Выполнить `python -m pytest -q` из общего окружения; проверить Checks интеграционного коммита.
- Перегенерировать `python scripts/export_contracts.py` и `python -m scripts.export_analytics_contracts`, сохранить изменения схем/примеров вместе с кодом.
- Не включать в Git пользовательские CSV, рабочую SQLite, окружения и секреты.
- Резервное копирование и проверенное восстановление — `python -m backend.app.db.backup`; параметры описаны в [BACKEND.md](BACKEND.md).
- Подключить фронтенд, проверить печать/CSV и полный сценарий T14. Публичный хостинг и материалы защиты требуют отдельного завершения.
