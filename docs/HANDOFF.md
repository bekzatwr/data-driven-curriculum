Актуальные поля, режимы и задачи владельцам — [P0_INTEGRATION.md](P0_INTEGRATION.md). Аналитика и frontend пока не опубликованы. P1 не расширяется до общего P0.

Готовые данные доступны уже сейчас в ветке `backend/bekzat`. До объединения её PR можно локально проверить сервер, клонировав эту ветку в отдельную папку. После проверки другим участником капитан объединяет PR; затем каждый обновляет свою рабочую ветку из `origin/main` по README. Никто не коммитит чужие задачи в ветку другого участника.

## Дамир — весь фронтенд

- Запустить backend по README. Базовый URL `http://127.0.0.1:8000`; для Vite заранее разрешены localhost и 127.0.0.1 на порту 5173.
- Экран загрузки: шаблоны → multipart `dry_run=true` → показать `counts`, `preview`, `warnings` → подтверждённая загрузка `dry_run=false` → сохранить возвращённый `dataset_id`.
- Кнопка «Демо»: `POST /api/datasets/demo`, затем `/filters`. Надпись о синтетических данных следует показывать при `source_type=demo`.
- `POST` 200 при повторе — успех. Для ошибок использовать `message` и `details`, а для полного файла — повторный запрос с `error_format=csv`.
- Фильтры классов/учебников отправлять повторяющимися query-параметрами, учитывать `total`, `limit`, `offset`.
- Аналитические экраны подключать к маршрутам Тони; план и отчёт — к маршрутам Айданы. Backend Бекзата не подставляет фиктивные метрики.
- Готовая сборка может раздаваться тем же сервером через `WEB_DIST_DIR=web/dist`.
- При открытии приложения запросить `GET /api/capabilities`: взять ограничения файлов/строк и доступность импорта/восстановления. В деморежиме оба действия отключены.
- Для блока «Паспорт данных» использовать `/datasets/{id}/quality`: `notices`, `by_topic`, `by_class`. `paired_post_share` находится в диапазоне 0–1; null показывать как «нет итоговых тестов». Это полнота записей, не процент всех учеников школы.
- «Скачать набор»: GET `/datasets/{id}/package` с сохранением JSON-файла. «Открыть набор»: отправить прочитанный JSON целиком в POST `/datasets/restore?dry_run=true`, показать preview/warnings, после подтверждения повторить с `false`. Новые страницы или кнопки реализует Дамир в своей ветке; все нужные серверные маршруты уже работают.

Контракты и JSON-примеры находятся в `contracts/`; примерные ID не являются существующими наборами. Всегда использовать ID из фактического ответа API.

## Тони — аналитика

Рекомендуемые файлы: `backend/app/analytics/`, `backend/app/api/analytics.py`. `Store.load_results` отдаёт до 10 000 валидированных строк целиком; результат HTTP `/results` по умолчанию содержит только 1000. Нули сохранены, отсутствующий учитель — null; отсутствие пары не превращается в нулевой прирост. `test_version` и `max_score` сохранены, чтобы можно было проверять сопоставимость.

Паттерн подключения (пример, не реализованный endpoint аналитики):

```python
from fastapi import APIRouter
from backend.app.api.datasets import StoreDep

router = APIRouter(prefix="/api", tags=["Analytics"])

@router.get("/datasets/{dataset_id}/topics")
def topics(dataset_id: str, store: StoreDep):
    records = store.load_results(dataset_id)
    constraints = store.get_topics(dataset_id)
    # Здесь вернуть результат вашей compute_topics, включая предупреждения.
```

Синхронный `def` выполняется FastAPI вне event loop. После готовности роутера подключить его в точке сборки:

```python
from backend.app.main import create_app
from backend.app.api.analytics import router as analytics_router
app = create_app(routers=(analytics_router,))
```

Можно создать отдельный `backend/app/team_main.py` с этим кодом и запускать `uvicorn backend.app.team_main:app`. При интеграции Бекзат подключит оба готовых роутера в общую точку входа. До появления модулей отсутствующих импортов в сервере нет.

`backend/app/demo.py` содержит детерминированный транспортный демонабор для проверки API. Тони дополняет его сценариями аналитики и проверяет формулы; после смены данных новая контрольная сумма создаст отдельный демонабор.

Паспорт `/quality` считает только полноту имеющихся записей и не заменяет аналитические метрики Тони. Для сопоставимости групп, прироста, статистических ограничений и сравнения учебников по-прежнему использовать свой модуль. JSON-пакет переносит исходные данные, не рассчитанные показатели.

## Айдана — планы, отчёты, P1

Файлы: `backend/app/planner/`, `backend/app/api/plans.py`. Читать исходные ограничения через `Store.get_topics`, данные — через `Store.load_results`. Подключение APIRouter такое же, как для Тони.

В `plans` подготовлены: id, dataset_id, class_id, created_at, algorithm_version, thresholds, constraints_snapshot, metrics_snapshot, hours_snapshot, manually_edited. Поля снимков/порогов — JSON-строки. Хранить рассчитанный снимок, не менять исходный набор и ограничения. Пример транзакционного доступа — `with store.connect() as db:`; значения передавать SQL-параметрами.

В `plan_reviews` подготовлены связи с планом и повторным набором, даты занятий, фактические часы, флаг соответствия ID, комментарий, снимок метрик, версия алгоритма и время создания. Для P1 перед расчётом:

```python
from backend.app.review_inputs import validate_review_structure

review = validate_review_structure(request_json, topic_ids={t["topic_id"] for t in plan_topics})
```

Валидатор проверяет обязательные поля, форматы дат, `started_on ≤ completed_on`, наличие целых неотрицательных фактических часов ровно по всем темам, строгий boolean для подтверждения ID. Строки "false"/"2", дробные/отрицательные часы и неизвестные поля отклоняются. Различие фактических и предложенных часов допустимо.

`identity_mapping_confirmed=false` сохраняется как false; модуль сопоставления должен явно запретить объединение учеников без подтверждения. Тони проверяет совместимость тестов и порядок дат для каждой пары `baseline ≤ started_on ≤ completed_on ≤ followup`; структурный валидатор не вычисляет метрики и не подменяет эти проверки. Айдана реализует preview/save/get, проверку ссылок/класса и сохранение снимка. В публичном деморежиме маршруты планов и P1 должны ограничиваться демонаборами через `store.get_dataset`.

## Что передано капитану

- Backend и тесты находятся в `backend/bekzat`; готовы к проверке через PR в `main`.
- Исходные загруженные файлы, SQLite, окружение и секреты не включаются в Git.
- Команды локального запуска, Docker и тестов есть в README и BACKEND.md.
- Резервное копирование и проверенное восстановление — `python -m backend.app.db.backup`; точные команды и ограничения в BACKEND.md. Доступны только оператору сервера через терминал.
- Публичный хостинг, интеграция готового frontend и сквозная проверка аналитика → план → отчёт выполняются после готовности модулей команды.
