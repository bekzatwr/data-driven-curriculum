# Backend Бекзата

Реализованы хранение и импорт данных, API наборов и фильтров, воспроизводимое демо, проверка структуры P1, локальный запуск и конфигурация контейнера. Аналитика, рекомендации по часам, сохранение рассчитанных планов и интерфейс принадлежат другим модулям команды. Отсутствующие маршруты возвращают 404.

## Запуск и установка

Проверенная версия Python — 3.13.3. Из корня репозитория:

```bash
python scripts/start.py
```

Первый запуск требует интернет для установки пакетов. Следующие запуски используют `.venv`; зависимости переустанавливаются при изменении lock-файла. Адрес сервера — `http://127.0.0.1:8000`, документация — `/docs`, OpenAPI — `/openapi.json`. База создаётся при старте в `data/curriculum.sqlite3`. Папка `data/` исключена из Git. Остановка — Ctrl+C.

Режим разработки и установка тестовых зависимостей:

```bash
python scripts/start.py --dev
python scripts/start.py --dev --install-only
```

Ручной запуск после установки, Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/benchmark_import.py --max-seconds 10
```

Linux/macOS:

```bash
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
.venv/bin/python -m pytest -q
.venv/bin/python scripts/benchmark_import.py --max-seconds 10
```

Если Windows выдаёт `WinError 5` для чужой/старой папки `pytest-of-user`, задайте отдельный корень тестовых временных файлов, не изменяя права системной папки:

```powershell
$env:PYTEST_DEBUG_TEMPROOT=(New-Item -ItemType Directory -Path data/test-tmp -Force).FullName
.\.venv\Scripts\python.exe -m pytest -q
```

## Настройки

Переменные окружения читаются при запуске. Файл `.env` Python автоматически не загружает.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_PATH` | `data/curriculum.sqlite3` | Относительные пути считаются от корня репозитория |
| `READ_ONLY_DEMO` | `false` | `true`: импорт запрещён, доступны только синтетические наборы |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Разрешённые адреса фронтенда через запятую |
| `WEB_DIST_DIR` | не задана | Папка готовой сборки Дамира с `index.html` |

Пример локального деморежима:

```powershell
$env:READ_ONLY_DEMO='true'
python scripts/start.py
```

`READ_ONLY_DEMO=true` блокирует и проверочный импорт, скрывает ранее загруженные наборы из списка и по прямому ID. `POST /api/datasets/demo` остаётся доступен и идемпотентен. Локальный режим без авторизации слушает `127.0.0.1`; публичный сервер следует запускать с `READ_ONLY_DEMO=true`. Настоящие данные детей не предназначены для открытого демо.

Когда Дамир подготовит сборку:

```powershell
$env:WEB_DIST_DIR='web/dist'
python scripts/start.py
```

Сервер раздаёт готовые файлы и `index.html` для маршрутов SPA. Он не собирает frontend. Команды установки и сборки `web/` добавляет Дамир. Несуществующий `/api/...` сохраняет JSON-ошибку 404.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/health` | Состояние сервера/SQLite, версия, деморежим |
| `GET /api/templates/results.csv` | Заголовок шаблона результатов, UTF-8 BOM |
| `GET /api/templates/curriculum.csv` | Заголовок шаблона учебного плана |
| `POST /api/datasets/import?dry_run=true` | Проверка двух CSV, счётчики, первые 10 записей каждого файла, предупреждения; без записи в БД |
| `POST /api/datasets/import?dry_run=false` | Повторная полная проверка и атомарная запись; 201 для нового набора, 200 для повтора |
| `POST /api/datasets/demo` | Загрузка встроенного синтетического демо, 201/200 |
| `GET /api/datasets?limit=50&offset=0` | Список наборов, `items`, `total`, пагинация; limit 1–100 |
| `GET /api/datasets/{id}` | Метаданные и счётчики набора |
| `GET /api/datasets/{id}/filters` | Классы, учебники, темы и версии тестов со шкалами |
| `GET /api/datasets/{id}/curriculum` | Ограничения часов по темам в порядке `topic_order` |
| `GET /api/datasets/{id}/results` | Валидированные исходные результаты с пагинацией |

Фильтры `/results`: повторяющиеся `class_ids` и `textbook_ids`, одиночные `topic_id`, `stage=pre|post`, `test_version`. Между разными фильтрами действует AND, внутри списка — OR. Отсутствующий фильтр означает все значения; неизвестное значение даёт пустую выборку. Пагинация: `limit` 1–1000 (по умолчанию 1000), `offset` от 0; `total` — число строк после фильтрации, до пагинации. Порядок: `student_id`, `topic_id`, `stage`. Фронтенд должен учитывать пагинацию.

Пример: `/api/datasets/{id}/results?class_ids=7A&class_ids=7B&topic_id=fractions&stage=post&limit=100&offset=0`.

Для импорта используется `multipart/form-data`: файлы `results_file`, `curriculum_file` и строковое поле `metadata` с JSON. Content-Type с boundary должен сформировать HTTP-клиент. Сначала отправить `dry_run=true`, показать пользователю результат, затем те же файлы с `dry_run=false`. Проверка не выдаёт токен и не хранит временный набор.

```json
{
  "name": "Математика — осень 2026",
  "subject": "Математика",
  "grade": 7,
  "period_start": "2026-09-01",
  "period_end": "2026-10-31"
}
```

`grade` — целое число 1–12, даты — строки YYYY-MM-DD; начало не позже конца. Неизвестные поля метаданных отклоняются.

## CSV

Кодировка UTF-8 с BOM или без него, разделитель запятая, десятичный разделитель точка. Порядок столбцов свободный, набор столбцов должен точно совпадать с шаблоном. Пробелы по краям значений удаляются. Заголовок и минимум одна строка данных обязательны. Пустые физические строки пропускаются. Поле с запятой заключить в двойные кавычки.

До 10 МБ суммарно для двух файлов, до 10 000 результатов, до 100 тем. Дополнительно ограничен весь HTTP body: 10 МБ + 64 КиБ на multipart и метаданные, включая передачу без Content-Length. Превышение размера — 413, числа строк — 422.

`results.csv` — одна строка на ученика, тему и этап:

```csv
student_id,school_id,class_id,teacher_id,textbook_id,topic_id,test_version,stage,score,max_score,tested_at
S001,SCHOOL1,SCHOOL1-7A,T1,BOOK-A,fractions,v1,pre,4,10,2026-09-01
S001,SCHOOL1,SCHOOL1-7A,T1,BOOK-A,fractions,v1,post,7,10,2026-10-01
```

| Поле | Правило |
| --- | --- |
| `student_id` | Псевдоним, уникальный в пределах набора; одна школа и класс |
| `school_id`, `class_id` | Непустые; код класса относится к одной школе (при нескольких школах используйте префикс школы) |
| `teacher_id` | Столбец обязателен, значение может быть пустым; в JSON это `null` |
| `textbook_id`, `topic_id`, `test_version` | Непустые; тема должна существовать в curriculum |
| `stage` | Только `pre` или `post` |
| `score`, `max_score` | Конечные числа; `max_score > 0`, `0 ≤ score ≤ max_score`; пустое значение не заменяется нулём |
| `tested_at` | Существующая дата YYYY-MM-DD внутри периода набора |

Идентификаторы и названия — до 120 символов, без управляющих знаков. Дубли `(student_id, topic_id, stage)` отклоняются. Для пары pre/post одинаковы учебник, версия теста и шкала; дата pre не позже post. Одна версия теста по одной теме имеет одну шкалу во всём наборе. Изменённый тест следует обозначить другой версией; текущий импорт не объединяет несовместимые pre/post.

`post` без `pre` допустим: сохраняется итоговый результат и предупреждение `MISSING_PRE`. `counts.pairs` — число пар «ученик + тема», а не число уникальных учеников. Вычисление прироста и покрытия выполняет модуль Тони.

`curriculum.csv` — одна строка на тему:

```csv
topic_id,topic_name,topic_order,current_hours,min_hours,max_hours,importance,is_locked
fractions,Дроби,1,6,3,8,3,false
geometry,Геометрия,2,3,2,5,2,true
```

`topic_id` и `topic_order` уникальны. Порядок и часы — целые неотрицательные числа до 9 цифр. `min_hours ≤ current_hours ≤ max_hours`, `importance` — 1, 2 или 3, `is_locked` — true/false. Импорт сохраняет исходные ограничения; распределение часов выполняет Айдана.

## Ошибки и повторный импорт

Ошибка JSON содержит `code`, `message`, `details`, `total_errors`. Каждая строковая ошибка содержит `file`, `row`, `field`, `reason`. `row` — номер физической строки CSV с заголовком как строкой 1; у многострочного поля это последняя строка записи. Для ошибок уровня запроса номер может быть null.

В JSON возвращаются первые 100 ошибок. Чтобы скачать все ошибки, повторить импорт с `error_format=csv`; CSV возвращается со статусом 422 и `Content-Disposition: attachment; filename="import-errors.csv"`. Ошибка без строковых деталей, например 413, остаётся JSON. Ошибки самого multipart или обязательных параметров также возвращаются JSON.

Если есть хотя бы одна ошибка, весь набор отклоняется. SQLite-транзакция дополнительно откатывает запись при сбое во время сохранения. SHA-256 вычисляется по нормализованным метаданным, темам, результатам и типу источника: повтор с переставленными строками/колонками и эквивалентными числами получает прежний `dataset_id`. Изменение имени/периода/данных создаёт новый набор. Встроенное демо (`source_type=demo`) отделено от ручной загрузки (`upload`).

## Файлы демо и запрос из терминала

```bash
python scripts/export_demo.py
```

Файлы появятся в `data/demo-input/`. Для PowerShell использовать `curl.exe`, чтобы не попасть в псевдоним Invoke-WebRequest:

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/datasets/demo
curl.exe -X POST "http://127.0.0.1:8000/api/datasets/import?dry_run=true" -F "results_file=@data/demo-input/results.csv" -F "curriculum_file=@data/demo-input/curriculum.csv" -F "metadata=<data/demo-input/metadata.json"
```

В Bash те же аргументы передать `curl`. Для сохранения изменить `dry_run=true` на `false`.

## SQLite и интеграция

На каждую операцию открывается отдельное соединение, включены foreign keys и WAL. Запись использует `BEGIN IMMEDIATE`; два одинаковых параллельных запроса сохраняют один набор. Схема версии 1, повторный запуск её не стирает. Более новая версия схемы вызывает явную ошибку вместо понижения версии. Изменения схемы после первого объединения нужно оформлять миграциями.

Таблицы: `datasets`, `topics`, `results`, а также контракт хранения `plans` и `plan_reviews`. Алгоритмы и API записи планов/проверок не входят в этот модуль. Поля снимков хранятся JSON-строками. Точные столбцы и связи — `backend/app/db/schema.sql`.

Для внутреннего расчёта брать все строки через `Store.load_results(dataset_id, **filters)`, а не первую страницу HTTP `/results`. Методы Store синхронные; в `async def` вызывать их через thread pool. Пример подключения — [HANDOFF.md](HANDOFF.md).

## Контейнер и публикация

```bash
docker compose up --build
docker compose down
```

Compose слушает `127.0.0.1:8000`, включает деморежим и хранит SQLite в именованном volume `curriculum-data`. `down` сохраняет данные; `down -v` удалит их. Для закрытого локального импорта можно установить `READ_ONLY_DEMO=false` перед запуском Compose.

Образ запускает Uvicorn на `0.0.0.0:8000` с одним worker под непривилегированным пользователем. Для хостинга нужны контейнер, постоянный диск на `/app/data`, HTTPS и `READ_ONLY_DEMO=true`; домен фронтенда добавить в `CORS_ORIGINS`. Healthcheck: `/api/health`. Публикация на внешнем хостинге не выполнялась: аккаунт/хост не выбран. Docker-конфигурация проверена через `docker compose config`; сборка и запуск контейнера на текущей машине не проверены, поскольку Docker daemon не запущен.
