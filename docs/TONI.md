# Аналитика Тони

Реализован пакет P0 Тони из разделов 6, 7, 9–11 ТЗ: метрики тем, проблемные темы, парное сравнение учебников, три маршрута API, воспроизводимые CSV, примеры ответов и проверки формул. Расчёты не зависят от HTTP, базы данных или внешних AI-сервисов. Модуль включён в общий сервер вместе с backend Бекзата и планировщиком Айданы в ветке `analytics/toni`. Весь интерфейс остаётся задачей Дамира; размещение стенда и командная проверка выполняются отдельно.

## Запуск и проверки

Основной запуск из корня репозитория, Python 3.13+:

```powershell
python scripts/start.py
```

Swagger — `http://127.0.0.1:8000/docs`. Стандартное приложение включает импорт, аналитику, сравнение и планы. Выполните `POST /api/datasets/demo` и используйте `dataset_id` из ответа. Для разработки и проверки:

```powershell
python scripts/start.py --dev --install-only
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_analytics*.py" -v
.\.venv\Scripts\python.exe scripts/export_contracts.py
.\.venv\Scripts\python.exe -m scripts.export_analytics_contracts
.\.venv\Scripts\python.exe -m scripts.export_analytics_demo --output-dir examples/toni-demo
.\.venv\Scripts\python.exe -m scripts.benchmark_analytics
```

В Linux/macOS используйте `.venv/bin/python`. Общие зависимости находятся в `requirements-dev.txt`; не устанавливайте старые зависимости отдельных planner/analytics демо поверх общего окружения. Интеграционные тесты теперь запускаются вместе с остальными: backend находится в этом checkout.

Для отдельной демонстрации только аналитики доступен `python -m uvicorn analytics.app:create_demo_app --factory --reload`. Её фиксированный ID — `toni-demo`; он не используется в общем сервере. Изолированное приложение не предоставляет импорт, сохранение плана или отчёт.

## Контракт для Дамира

| Метод и маршрут | Ответ |
| --- | --- |
| `GET /api/datasets/{id}/overview` | `metrics`, `topics`, `heatmap` |
| `GET /api/datasets/{id}/topics/{topic_id}` | `metrics`, `by_class`, `slices` |
| `GET /api/datasets/{id}/comparison` | `group_a`, `group_b`, `comparison_status`, `difference_gain_pp`, `reasons`, `conclusion` |

Общие поля: `dataset_id`, `is_demo`, `source`, `applied_filters`, `settings`, `warnings`. Источник содержит предмет, параллель и период одного неизменяемого набора. `is_demo` отражает доверенный серверный `source_type`, а не текст имени файла.

Обзор и детали принимают `class_ids`, `textbook_ids`, `test_version`. Массивы передаются повторяемыми query-параметрами: `?class_ids=7A&class_ids=7B`. Пропущенный или пустой список означает все значения. Сравнение принимает обязательные `topic_id`, `textbook_a`, `textbook_b`, а также `class_ids` и `test_version`. Неизвестные фильтры возвращают 422; неизвестный набор или тема — 404; существующее пустое пересечение фильтров — 200 с `null`, нулевыми счётчиками и пустой тепловой картой.

Пример сравнения отдельного демо: тема `equations`, учебники `Учебник A` и `Учебник B`. В Swagger значения вводятся текстом; API-клиент должен кодировать query штатными средствами. Одинаковые учебники и пересечение учеников между группами отклоняются с 422.

`TopicMetrics.status` принимает `requires_attention`, `needs_practice`, `mastered`, `insufficient_data`, `no_data`, `mixed_versions`. Для подписи доступен `status_label`. `problem_topic` — отдельный признак: например, при среднем 64% и доле низких результатов 40% он равен `true`, хотя статус — «Нужно закрепление». При недостаточном числе результатов он `false`; при отсутствии определимого показателя — `null`.

Тепловая карта содержит `{school_id, class_id, metrics}` на каждую тему и класс выбранной группы. Детали возвращают отдельные срезы `test_version + max_score`. При смешении версий общий средний темы и обзора — `null`, доступные срезы перечислены в `available_slices`. Выбор `test_version` применяется ко всем показателям, включая pre/post. Разные шкалы с одним ID версии должны отклоняться импортом; чистые функции дополнительно не объединяют их.

Карточки обзора:

- `n_students` — уникальные ученики среди выбранных pre/post; `n_post_students` — ученики хотя бы с одним post.
- `n_post_results` и `n_pairs` — количества результатов и пар **ученик–тема**, не количества людей.
- `pair_coverage = n_pairs / n_post_results`; `n_paired_students` — уникальные ученики хотя бы с одной парой; `paired_student_share = n_paired_students / n_post_students`.
- `n_complete_students` — ученики с post по всем темам учебного плана; `topic_count` — количество тем. Неполное покрытие явно отмечено.
- `mean_post_pct` — сначала среднее по доступным темам каждого ученика, затем среднее этих индивидуальных средних. Ученик с большим числом результатов не получает больший вес.

`below_threshold_share`, `pair_coverage` и `paired_student_share` — доли 0–1; баллы — проценты 0–100; прирост и его разность — п.п. Внутренние результаты не округляются. Клиент показывает один знак после запятой, умножает доли на 100 только для отображения и сохраняет различие между `null` и нулём.

Сравнение: `comparison_status` — `comparable`, `insufficient_data` или `not_comparable`. `difference_gain_pp = gain_A - gain_B` доступно только при `comparable`, иначе строго `null`. `baseline_gap_pp` — абсолютный разрыв входных средних на одной шкале. `mean_post_pct` группы — все её post; `mean_post_paired_pct`, `mean_pre_paired_pct` и `mean_gain_pp` — одни и те же ученики с совместимой парой. `n_classes` и `n_teachers` описывают парную выборку; отсутствующий ID учителя не считается отдельным учителем и отмечается предупреждением.

Это текущий контракт реализации Тони. Предварительный `analytics-p0.proposed.openapi.json` Бекзата заменён действующей OpenAPI: добавлены реальные статусы тем, статус недостаточной выборки, размеры классов/учителей и покрытие. Поля сравнения названы `comparison_status` и `difference_gain_pp`, как в ТЗ; не используйте имена `status`/`gain_difference_pp` из предварительной схемы. Текущая схема отдельного демо — `contracts/analytics.openapi.json`; живая схема доступна на `/openapi.json`.

## Методология

Нормированный результат — `100 * score / max_score`. Низкий результат — строго меньше 60%. При 10 и более post: среднее <60% требует внимания, [60%,80%) требует закрепления, ≥80% считается освоенным в рамках прототипа. Проблемная тема имеет среднее <60% **или** долю низких результатов ≥40%. Пороги описывают решения MVP, а не утверждённую педагогическую диагностику.

Парой считается один ученик и тема с pre/post, одинаковыми учебником, версией, шкалой, школой и классом. Дубликат этапа вызывает ошибку, а не заменяет предыдущую запись. Без pre итоговый результат сохраняется, прирост не вычисляется. Отрицательные приросты сохраняются.

Для численного сопоставления нужны один набор и тема, единая версия/шкала, минимум 10 пар в каждой группе и стартовый разрыв не более 10 п.п. Никакие версии автоматически не объявляются эквивалентными. При нарушении правил возвращаются причины, а сравнительная разность скрывается. Каждое сравнение содержит предупреждение об отсутствии причинного вывода; один класс или учитель дополнительно отмечается. P-value, рейтинги «лучший учебник» и обещания эффекта не рассчитываются.

## Демоданные

`examples/toni-demo/` содержит UTF-8 CSV и метаданные: 120 условных учеников, 4 класса, 6 тем, 2 условных учебника, 1440 строк, 24 предстоящих часа. Данные полностью искусственные и детерминированы. Все основные пары полные, как требует T01; отсутствующие pre, малые выборки, ошибки и версии проверяются отдельными тестовыми сценариями.

Тема «Уравнения»: A — 60 пар, 2 класса, средние 52→68%, прирост 16 п.п.; B — 60 пар, 2 класса, 53→61%, прирост 8 п.п. Разность 8 п.п. вычисляется из CSV. «Дроби» показывают низкий средний балл; «Пропорции» — 40% низких результатов при среднем 64%; «Статистика» и «Повторение» предоставляют освоенные темы для планировщика; геометрия заблокирована. Значения не подставляются в интерфейс.

Если CSV импортировать как пользовательский файл, backend корректно сохраняет `source_type=upload` и `is_demo=false`, даже если название предупреждает об искусственных данных. Общий `/api/datasets/demo` уже подключён к этому генератору и задаёт доверенный `source_type=demo`.

## Интеграция с общим сервером

Backend `f274142` объединён в `analytics/toni`. Стандартный `backend.app.main.create_app()` подключает аналитический роутер, обработчик ошибок и планировщик. `analytics` и `textbook_comparison` в `/api/capabilities` равны `true`; Docker включает пакет аналитики. Ручной патч или дополнительная настройка роутеров не нужны. Совместимая фабрика `analytics.app:create_integrated_app` остаётся доступной и не дублирует маршруты.

Адаптер использует `app.state.store`, `get_dataset`, `get_topics`, `load_results`. Полный внутренний `load_results` исключает потерю записей из-за HTTP-пагинации. Проверка доступа к набору выполняется до вычислений, поэтому публичный деморежим не раскрывает пользовательские загрузки.

Основная схема общего API — `contracts/openapi.json`; схема отдельного демо — `contracts/analytics.openapi.json`. После изменений запускайте оба генератора контрактов в общем окружении и сохраняйте их результат вместе с кодом. Предварительный контракт заменён действующими схемами.

Планировщик сохраняет итоговые показатели выбранного класса, параметры и часы в неизменяемом снимке. Полная аналитика тем и сравнение учебников не добавляются в `SavedPlan` автоматически. Для отчёта используйте сохранённый `GET /api/plans/{id}`, не текущий overview или comparison.

## Проверки и оставшаяся командная работа

Тесты проверяют T01, T04, T05, T07, T08, фильтры, границы 60/80%, 9/10 учеников, долю 40%, стартовый разрыв 10 п.п., отрицательные приросты, смешанные версии, дубликаты, пустые выборки и отсутствие округления до агрегации. Дополнительная интеграционная проверка проходит путь импорт → аналитика → сравнение → план → сохранённый отчёт → CSV → перезапуск и проверяет ограничения публичного деморежима.

При общем прогоне обнаружена незакрытая SQLite-сессия в прежнем `planner/storage.py` из main: Windows не мог удалить тестовую базу. Перенесено идентичное исправление `contextlib.closing`, уже присутствующее у Бекзата; правила расчёта часов не менялись.

Для 10000 строк `scripts/benchmark_analytics.py` измеряет три вызова полного overview через TestClient, включая фильтрацию, расчёты, Pydantic и сериализацию. Локально 10 ноября 2026 на Windows/Python 3.12 получено 0,181 / 0,279 / 0,187 с — ниже цели 2 с. Замер не включает реальную БД или сеть; это проверка модуля, не замена командного измерения импорта/плана.

Серверные маршруты объединены. Остаются подключение экранов Дамиром, ручной сценарий T14, измерение полного стенда, размещение при необходимости и презентация/видео. Готовность вычислительного пакета Тони не означает готовность всего приложения.

Для объединённого сервера `python scripts/benchmark_pipeline.py` выполняет три импорта по 10000 строк в новые SQLite, затем обзор и план. Локальные результаты сохранены в [benchmark-pipeline.json](benchmark-pipeline.json): максимум импорта 1,099 с, обзора 0,363 с, плана 0,073 с. Измеряются HTTP-обработчики через TestClient и настоящая SQLite, без сетевого соединения и запуска процесса.
