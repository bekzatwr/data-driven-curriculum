# P1 Тони: нагрузка учителей и методология

База — `integration/p0-server`, изменения — `analytics/toni`. Сервер рассчитывает нагрузку из всех сохранённых результатов набора, а не из первой страницы `/results`. UI, транспорт ИИ, комментарии и алгоритм плана на период остаются отдельными частями команды.

## API и формулы

`GET /api/datasets/{dataset_id}/teachers` поддерживает повторяемые `class_ids`, `textbook_ids` и одну `test_version`, как `/overview`. Неизвестные фильтры возвращают структурированную ошибку 422, неизвестный или недоступный набор — 404. Известные фильтры с пустым пересечением дают 200, пустые массивы и `null` вместо деления на ноль. В публичном деморежиме доступны только доверенные демоданные.

Ответ включает envelope (`dataset_id`, `is_demo`, `applied_filters`, `settings`, `warnings`), `teachers`, `schools`, `total`, `hours_per_class`, `missing_teacher_rows`, `definitions`. Полные схемы и реальные ответы: [OpenAPI](../contracts/openapi.json), [единый сервер](../contracts/integrated-analytics-teachers.response.json), [демоприложение аналитики](../contracts/analytics-teachers.response.json).

| Поле | Определение |
| --- | --- |
| `teacher_id`, `school_id` | Учитель внутри школы; одинаковые ID в разных школах разделены |
| `class_ids`, `textbooks` | Уникальные наблюдаемые классы и учебники учителя по обеим стадиям |
| `students` | Уникальные ученики учителя по обеим стадиям |
| `hours_per_class` | Сумма `current_hours` всех тем учебного плана; фильтр результатов её не меняет |
| `upcoming_hours` | Число наблюдаемых классов учителя × `hours_per_class` |
| `mean_post_pct` | Среднее `score / max_score × 100` по итоговым записям ученик–тема, как в UI; каждая запись имеет одинаковый вес |
| `n_post`, `n_post_students` | Число итоговых записей ученик–тема и число уникальных учеников с итогом соответственно |
| `n_pairs`, `mean_gain_pp` | Число совместимых пар ученик–тема; среднее `post_pct − pre_pct`, в п.п. |
| `pair_coverage` | `n_pairs / n_post`, доля 0–1; без итогов — `null` |
| `n_paired_students` | Уникальные ученики хотя бы с одной совместимой парой; несколько тем одного ученика считаются один раз |
| `paired_student_share` | `n_paired_students / n_post_students`, доля 0–1; без учеников с итогом — `null` |
| `is_missing_teacher` | Группа записей без установленного учителя; это не дополнительный педагог |

Пары требуют совпадения школы, группы учителя, класса, учебника, версии и шкалы. При смене учителя между pre/post прирост не приписывается одному из них. Пары в группе без учителя описывают учеников и не доказывают, что преподаватель был один. Если внутри одной темы смешаны версии или шкалы, оба средних учителя — `null`; `mixed_topic_ids` и `warnings` объясняют ограничение, нагрузка и счётчики остаются доступны.

`mean_post_pct` учителей намеренно сохраняет взвешивание записей из UI. В `/overview` сначала усредняются результаты каждого ученика, затем ученики имеют одинаковый вес: при разном количестве тем эти средние могут различаться. `n_pairs=180` у одного демоучителя означает 30 учеников × 6 тем, а не 180 учеников. Пустые значения не заменяются нулём; реальный нулевой балл сохраняется.

Покрытие парными тестами показано отдельно по записям и по ученикам. Например, при итоговых тестах 30 учеников по шести темам и входных тестах только одного ученика `n_pairs=6`, `n_paired_students=1`, `paired_student_share=1/30`. Прирост остаётся описательным и сопровождается предупреждением, если число учеников с парой больше нуля, но меньше `settings.min_students` (по умолчанию 10). Порог относится к ученикам, а не к числу тем или пар; его достижение не делает результат оценкой учителя или причинным эффектом. Если итоги есть, но совместимых пар нет, доля учеников с парой равна 0, а прирост — `null`; без итогов доля — `null`.

Для школы и `total`: `teachers` — число известных групп школа–учитель, `students` — все уникальные ученики выбранного среза, `classes` — уникальные пары школа–класс. Формулы:

- `students_per_teacher = students / teachers`;
- `classes_per_teacher = число связей известный учитель–класс / teachers`;
- `hours_per_teacher = число таких связей × hours_per_class / teachers`.

Без известных учителей отношения равны `null`. Ученики без teacher_id входят в население школы, но неизвестная группа не входит в число учителей и связей. Поэтому `students_per_teacher` — отношение школьных итогов, а не среднее полей `teacher.students`. При совместных назначениях или смене учителя один класс может учитываться у нескольких учителей; API предупреждает об этом. Это оценка по наблюдаемым связям, а не подтверждённое расписание или полная ставка.

## Проверка демо и переключение UI

[Фактическая сверка](teachers-ui-parity.json): исходный `web/src/lib/teachers.ts` из коммита `03395ef5db68ac9fab379f622ddf6fbe09112327` выполнен Node 24.22.1 и сопоставлен с Python. Все 56 проверенных значений совпали, максимальная разница 0 при допуске `1e-10`.

Сверка воспроизводится командой ниже; нужны Node.js 24+ и локальная история Git с указанным коммитом. Скрипт получает неизменённый TypeScript через `git show`, запускает его во временном каталоге и сравнивает с текущим Python. Он не скачивает код или пакеты и не использует сохранённый результат вместо запуска. Параметром `--node` можно указать полный путь к Node. Отсутствие исходного коммита, Node или обязательного поля, а также расхождение значений завершают проверку ошибкой. CI выполняет её на Windows и Linux.

```powershell
python scripts/verify_teachers_parity.py --output data/teachers-ui-parity.json
```

Отчёт хранит обе фактические выдачи, версию среды и хеши исходников/входа. Для переносимости хеши текстовых исходников нормализуют окончания строк к LF; отдельно сохраняется хеш точных байтов исполненного TypeScript. Дополнительные серверные поля покрытия перечислены отдельно и проверяются серверными тестами. Ноль, `null` и `false` при сравнении различаются; повторяющиеся элементы не удаляются.

Результат: 4 учителя, 120 учеников, 30 учеников на учителя, 24 часа на класс и учителя. У каждого — 180 итоговых результатов и 180 пар. T1/T2: итог 72.3333%, прирост 12.1667 п.п.; T3/T4: итог 71.1667%, прирост 10.8333 п.п. Отображение можно округлить, API сохраняет точность.

Сервер дополнительно исправляет смешение одинаковых teacher_id между школами, коллизию настоящего ID «Не указан» с пропуском и недопустимое объединение версий. Это намеренные отличия для пограничных данных, а не заявление о полном совпадении со старым UI на любых входах.

Для подключения Дамиру:

1. Проверять `GET /api/capabilities` → `features.teachers_api=true`, добавить API-вызов `/teachers` с общими фильтрами. В `fix/damir-final-integration` также есть локальный `TEACHERS_SERVER_CONNECTED`: включить его после подключения.
2. Использовать готовые `teachers`, `schools`, `total`; не загружать `/results` для повторного вычисления. Сохранять состояния загрузки, пустых данных и ошибки.
3. Ключ строки: `JSON.stringify([school_id, teacher_id, is_missing_teacher])`; определять неизвестного учителя по флагу, не по строке «Не указан».
4. Показывать `warnings` и `null` как отсутствие расчёта. Если сохраняется порог пометки `> 1.2 × среднее`, подписывать «более чем на 20% выше средней нагрузки». Баллы и прирост не использовать для рейтинга учителей.

## Воспроизведение

Расчёт нагрузки проверен на трёх валидных CSV по 10 000 строк и 100 тем: 20 учителей в школе, 10 000 учителей в школе, 10 000 учителей в 10 000 школах. Пустые темы больше не рассчитываются отдельно для каждого учителя, а группировка по школам использует индекс. Все поля результатов совпали с реализацией `d5fd35d` до оптимизации.

[Отчёт измерений](teachers-performance.json): в крайнем случае с 10 000 школами чистый расчёт занял 70,54 с до изменения (один прогон) и 1,00 с после него (медиана трёх); полный TestClient-запрос после изменения — 1,78 с. Это локальные измерения Python 3.13 на Windows с текущими общими helpers, не обещание производственной задержки. CSV сначала валидируется; время его подготовки и валидации не входит в измерение GET. CI использует предел 10 с для защиты от возврата медленного алгоритма.

```powershell
python scripts/benchmark_teachers.py --http --repeats 3 --max-seconds 10 --output data/teachers-performance.json
```

Для независимой проверки всех полей можно добавить `--baseline-ref d5fd35d`; прежний алгоритм на крайнем наборе выполняется существенно дольше. Измерения создают только временную БД.

```powershell
python -m pytest -q
python -m scripts.audit_ai_methodology --output docs/ai-methodology-offline.json
python -m scripts.export_analytics_contracts
python scripts/export_contracts.py
```

CI повторяет тесты и сверяет сохранённые контракты и offline-запросы с генерацией. Контейнерный smoke проверяет `/teachers`, флаг возможности и равенство ответа после перезапуска.
