# Серверная интеграция P0

Ветка `integration/p0-server` создана от `main:3ebe857` и объединяет `backend/bekzat:d83ce28` с `analytics/toni:a2a89fa`. Стандартный `backend.app.main.create_app()` включает импорт, аналитику тем, сравнение учебников, планирование и атомарное сохранение JSON/CSV-отчётов. Сохранены deployment-проверки и постоянный SQLite volume. Ручное подключение роутеров не требуется. Фронтенд ещё не включён; P1/P2 не расширяются до готовности общего P0.

[Рабочие endpoints и JSON для Дамира](FRONTEND_API.md) · [Технический review, конфликты и результаты проверок](SERVER_INTEGRATION_REVIEW.md). Merge в main — только после review Айданы и согласования команды.

## Запуск и хранение

Основной запуск из корня: `python scripts/start.py`; Swagger — `http://127.0.0.1:8000/docs`. Для разработки и тестов используйте `python scripts/start.py --dev --install-only`, затем Python из созданного `.venv`. Требуется Python 3.13 или новее; общие зависимости — `requirements.txt` и `requirements-dev.txt`. Старые зависимости из `requirements-planner.txt`/`requirements-analytics.txt` предназначены для отдельных демо и не устанавливаются поверх общего окружения.

Фабрики `analytics.app:create_integrated_app` и `planner.app:create_integrated_app` остаются совместимыми входами. Стандартный запуск уже подключает оба модуля; повторная передача того же роутера не создаёт дубликатов. Docker включает `backend`, `planner` и `analytics`.

Таблица `aidana_plan_snapshots` находится в `DATABASE_PATH` вместе с исходными наборами SQLite. Один volume и команда резервного копирования сохраняют данные и отчёты. Исходная схема backend версии 1 и подготовленные таблицы `plans`/`plan_reviews` сохранены; действующие снимки P0 хранятся в `aidana_plan_snapshots`. Изолированное демо Айданы по-прежнему использует `PLAN_DATABASE_PATH`: его старые снимки не переносятся автоматически.

## Единое демо

`POST /api/datasets/demo` использует `analytics.demo.demo_files`: 120 искусственных учеников, четыре класса, шесть тем, два учебника, 1440 строк и 24 предстоящих часа. Общий сервер возвращает UUID набора. Для темы `equations` прирост группы A — 16 п.п., группы B — 8 п.п., разность — 8 п.п.; значения рассчитываются из записей.

`source_type=demo` и `is_demo=true` задаются доверенным серверным демомаршрутом. Импорт тех же CSV сохраняет `source_type=upload`: название файла не даёт ему права обходить ограничения публичного режима. Новый демонабор может получить другой ID, если изменились данные или метаданные; старые наборы и их планы сохраняются.

## Интерфейс для Дамира

Базовый URL — `http://127.0.0.1:8000`. Разрешены Origins `http://localhost:5173` и `http://127.0.0.1:5173`; другие адреса задаются в `CORS_ORIGINS`. JSON-запросы используют `Content-Type: application/json`; multipart boundary формирует браузер.

1. `POST /api/datasets/import?dry_run=true`: FormData с `results_file`, `curriculum_file`, `metadata` как JSON-строкой. Показать `counts`, `preview`, `warnings`; повтор с `dry_run=false` сохраняет набор. HTTP 201 означает новый набор, 200 — уже существующий.
2. `GET /api/datasets/{id}/filters`: взять реальные ID классов, учебников, тем и версий. ID `toni-demo` и `aidana-demo` относятся только к отдельным демоприложениям.
3. `GET /api/datasets/{id}/overview`, `/topics/{topic_id}`, `/comparison`: получить готовые вычисления Тони. Подробные поля и единицы — [TONI.md](TONI.md).
4. `POST /api/datasets/{id}/plans/preview`: минимально `{"class_id":"7A"}`. Дополнительно доступны `test_versions: {topic_id: version}`, `constraints: {topic_id: {min_hours,max_hours,importance,is_locked}}`, `settings: {target_pct:70,donor_pct:80,min_students:10,max_change:2}`. План всегда строится для одного класса.
5. `POST /api/datasets/{id}/plans`: те же поля, дополнительно полная карта целых часов `hours_by_topic` и `comment`. Сервер повторно рассчитывает и проверяет ограничения. HTTP 201 возвращает `SavedPlan` с `plan_id`; повторное сохранение создаёт новый снимок.
6. `GET /api/plans/{plan_id}`: открыть отчёт из сохранённого ответа. `GET /api/plans/{plan_id}/export.csv` возвращает тот же вариант в CSV UTF-8 с BOM; заголовок `Content-Disposition` доступен через CORS.

`PlanPreview.items` содержит текущие и предложенные часы, ограничения, `delta`, `reason` и показатели. `SavedPlan` дополнительно содержит `recommended_hours`, `recommendation_reason`, `manually_modified`, `recommendation_transfers`. Снимок фиксирует источник, выбранный класс, итоговые показатели для планирования, настройки, часы, дату и комментарий. Полная страница аналитики и сравнение двух учебников в этот снимок не входят. Отчёт следует строить из `GET /api/plans/{id}`, а не пересчитывать по текущим фильтрам экрана.

`GET /api/capabilities`: `analytics`, `textbook_comparison`, `plan_preview`, `plan_save`, `plan_report`, `plan_csv` равны `true`. Импорт и восстановление доступны только вне публичного деморежима. Ошибки имеют поля `code`, `message`, `details`, `total_errors`: 404 — неизвестный или скрытый набор/план, 422 — неверные параметры, 503 — временная недоступность SQLite. `null` не заменять нулём; `is_demo` показывать пользователю. Даты хранятся в UTC, интерфейс отображает UTC+5.

## Контракт аналитики

Фильтры `class_ids` и `textbook_ids` передаются повторяемыми query-параметрами; `test_version` — одна выбранная версия. Для comparison обязательны `topic_id`, `textbook_a`, `textbook_b`, дополнительно доступны `class_ids`/`test_version`. Неизвестные фильтры отклоняются; известное пустое пересечение возвращает пустые показатели.

`TopicMetrics` включает средний итоговый процент, долю ниже порога 0–1, число итоговых результатов и пар, парные средние до/после, прирост, покрытие, статус, признак проблемной темы, версию/шкалу и предупреждения. Несовместимые версии не объединяются. `comparison_status` принимает `comparable`, `insufficient_data`, `not_comparable`; `difference_gain_pp` доступно только при `comparable`. Минимум — десять пар в каждой группе и стартовый разрыв не больше десяти п.п. Пересечение учеников отклоняется; сравнение не доказывает причинного эффекта учебника.

Действующие схемы: `/openapi.json`, `contracts/openapi.json` и `contracts/analytics.openapi.json`; реальные примеры — `contracts/analytics-*.response.json` и `contracts/integrated-analytics-*.response.json`. Предварительный `analytics-p0.proposed.openapi.json` заменён действующими схемами и удалён.

## Проверка и оставшаяся работа

Из общего окружения выполните `python -m pytest -q`, `python scripts/export_contracts.py` и `python -m scripts.export_analytics_contracts`. Изменения публичных полей должны сопровождаться обновлением схем и примеров. CI сверяет контракты с приложением; фактический результат конкретного коммита смотрите в его Checks.

Серверные тесты проверяют импорт → аналитика → сравнение → план → сохранённый JSON/CSV, перезапуск, резервное копирование, отсутствие дубликатов роутеров и закрытие загруженных наборов в публичном режиме. Контейнерный сценарий дополнительно проверяет сохранность состояния после реального перезапуска. Эти проверки не заменяют прохождение интерфейса.

| Этап | Состояние |
| --- | --- |
| Два CSV → проверенный набор | Реализовано с SQLite |
| Набор → аналитика тем и сравнение | Рабочие маршруты Тони включены в стандартный сервер |
| Набор → перераспределение часов | Модуль Айданы включён; сумма, границы и блокировки проверяются |
| План → сохранённый отчёт и CSV | Один неизменяемый снимок, проверка после перезапуска |
| Полный путь через интерфейс | Ожидает фронтенд Дамира и ручной сценарий T14 |

Остаются подключение экранов, проверка печати и скачивания, общий замер стенда, командный review и размещение при необходимости. Ограничение часов планировщика — не больше 10 000 на поле; импорт больших значений может пройти, но расчёт плана их отклонит. Публичный хостинг, презентация и видео не появляются от одной серверной интеграции. Дедлайн команды — 11 ноября 2026, 23:59 UTC+5.
