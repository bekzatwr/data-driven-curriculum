# React handoff и мобильная приёмка

Проверено 10 ноября 2026: `frontend/damir` остаётся на `7660b17`, содержит только `README.md` и ТЗ `.docx`. В актуальном main `3ebe857` React также отсутствует. **Все UI-проверки ниже заблокированы отсутствием приложения, а не пройдены.** Frontend вместо Дамира не создан; его код не изменён.

## Что требуется от Дамира

1. Опубликовать исходники в `frontend/damir` и открыть PR. Предпочтительный каталог `web`; если иной — согласовать `FRONTEND_DIR`, не перемещать файлы без владельца.
2. Передать `package.json`, `package-lock.json`, TypeScript config, `src`, HTML entrypoint и npm scripts `test`, `typecheck`, `lint`, `build`. Test script должен поддерживать однократный запуск `npm test -- --run`; build выдаёт `dist/index.html`.
3. Использовать только настоящий API из [FRONTEND_API.md](FRONTEND_API.md), относительный `/api`, UUID из ответов. Не использовать `toni-demo`/`aidana-demo`, mock JSON или прямой доступ к SQLite в общем приложении.
4. На старте читать capabilities. В public mode скрывать/отключать импорт, restore и save с понятным объяснением; показывать аналитику, preview и подготовленный отчёт. Нельзя эмулировать успешное сохранение в localStorage.
5. Согласовать UI-маршрут открытия отчёта по plan_id. Владелец выдаёт plan_id и API ссылки из `deploy/seed_demo_report.py`; frontend должен уметь открыть этот snapshot после refresh/прямой ссылки. Новый публичный endpoint списка планов в P0 не добавлялся.
6. Для ручных правок использовать полный `hours_by_topic`; сервер проверяет min/max, locked, ±2 и сумму. После HTTP 422 оставить введённые значения и показать ошибку.
7. Для отсутствующих метрик отображать «нет данных», не 0. Учитывать несопоставимые группы, mixed versions и предупреждения аналитики. Analytics attention=60% и planner target=70% — разные согласованные пороги.
8. Не помещать секреты в `VITE_*`, исходники, localStorage, frontend `.env` или сборку. В браузерном Network после build не должно быть запросов на localhost, file:// или HTTP с HTTPS-страницы.

Проверка исходников: `python scripts/check_frontend_handoff.py --directory web`. Это проверка комплектности, не тест качества реализации. Текущий результат — exit 2: package.json, lockfile, tsconfig и src отсутствуют.

## Ошибки, загрузка и Retry

- Ограничить ожидание ответа: предлагаемый бюджет 30 секунд с AbortController. После таймаута показать действие «Повторить», не бесконечный spinner.
- Для GET можно повторить после сетевой ошибки/503 ограниченное число раз с задержкой; кнопка ручного Retry остаётся доступна. Не повторять бесконечно.
- Для save запрещён автоматический повтор: при потере ответа после commit сервер мог сохранить план. Не показывать «сохранено» без успешного ответа и plan_id; предупредить о неопределённом результате. Идемпотентный ключ сохранения не добавлен в P0.
- Импорт повторного содержимого идемпотентен, но сначала показывать пользователю итог запроса. Во время submit блокировать двойной клик.
- 403 READ_ONLY_DEMO объясняет режим; 413 — размер файлов; 422 — ошибки CSV/плана; 404 — недоступный набор/отчёт; 503 — временная недоступность с Retry.
- Для FormData не задавать Content-Type вручную. В file picker принимать `.csv,text/csv`, но проверку расширения/данных доверять серверу. Выбранные имена и ошибки должны быть видны на узком экране.
- CSV скачивать с настоящего `/api/plans/{id}/export.csv`; проверять HTTP status до создания Blob. На Safari/iOS проверить открытие/сохранение через «Файлы»/share sheet и восстановление состояния после возвращения в браузер.

## Два E2E после получения React

**Локальный, отдельный writable volume и loopback-порт:** выбрать два синтетических CSV с диска/Files → увидеть неверный CSV и исправить → preview/import → overview → тема → сравнение учебников → planner → допустимая и недопустимая ручная правка → save → JSON report → CSV download → refresh/direct URL → restart → тот же plan_id. Экспорт сравнить со snapshot. Повторить после backup/restore в новый файл.

**Публичный HTTPS, READ_ONLY_DEMO=true:** открыть с другого устройства/мобильного интернета → capabilities → синтетический набор → обзор → тема → сравнение → preview → заранее подготовленный отчёт → CSV. Import/save отсутствуют либо отключены; прямые запросы записи дают 403. Проверить отсутствие CORS/mixed content, недоступный API и Retry. Внешнее устройство и HTTPS проверяются только после разрешённого deploy.

Для каждого запуска записать commit, URL, браузер/версию/ОС, физическое устройство или эмуляцию, viewport, dataset_id/plan_id, скриншот, network/console errors и результат. При дефекте: шаги, ожидание, факт, серьёзность, скриншот и endpoint. Передать Дамиру; изменения его frontend — только по согласованию.
