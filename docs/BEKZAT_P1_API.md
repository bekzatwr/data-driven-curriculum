## Комментарии

`GET /api/datasets/{dataset_id}/comments?target_type=&target_id=` → `200 {items,total}`. Максимум **500** элементов; `total` — число подходящих записей. Порядок: `created_at DESC, id ASC`, чтение total/items в одном snapshot. Фильтры точные; все запросы ограничены dataset.

`POST /api/datasets/{dataset_id}/comments` → `201 Comment`:

```json
{
  "target_type": "plan_topic",
  "target_id": "<plan_id>:fractions",
  "author_name": "Synthetic reviewer",
  "author_school": "",
  "author_role": "methodist",
  "text": "Review the synthetic plan"
}
```

`target_type`: dataset / topic / textbook / class / teacher / plan / plan_topic.

| Цель | Проверка принадлежности |
| --- | --- |
| dataset | `target_id == dataset_id`; совместимые anchors `overview`, `teachers` привязаны к dataset из URL |
| topic | Строка `topics(dataset_id, topic_id)` |
| textbook / class / teacher | ID существует в `results` этого dataset |
| plan | Snapshot из `aidana_plan_snapshots`; его `dataset_id` совпадает с URL |
| plan_topic | `<plan_id>:<topic_id>`; тот же dataset и тема входит в items сохранённого snapshot |

Имя 1–80, школа ≤120, текст 1–4000 символов; внешние поля запрещены, пробелы по краям удаляются, пустые строки отклоняются. `author_role` — подпись автора, **не аутентификация и не права администратора**. У приложения пока нет пользовательской авторизации; writable режим предназначен для приватного локального показа команды.

Новый комментарий сначала полностью валидируется и сериализуется в ответ, затем `BEGIN IMMEDIATE` проверяет цель/квоты, INSERT и commit. Ошибки формирования ответа и INSERT не оставляют комментарий. Соединения закрываются. Таблица остаётся в общей `DATABASE_PATH`; схема обновляется добавлением индексов/таблиц без удаления прежних записей и без изменения P0 `user_version`.

### Ограничения

- 10 POST/мин на IP, 60 POST/мин на весь сервис; учитываются также отклонённые запросы после проверки публичного режима.
- HTTP **429** содержит целое число секунд в `Retry-After`; заголовок доступен браузеру через CORS.
- До 5000 комментариев глобально, 1000 на dataset; до 8 МиБ UTF-8 значений строк; запрет новых comments при занятом DB+WAL бюджете 64 МиБ (с резервом). Ответ **409 `COMMENT_QUOTA_EXCEEDED`**. P0-запись не ограничивается квотой comments.
- JSON body ≤65536 байт до разбора, включая chunked; 413 `COLLAB_BODY_TOO_LARGE`.
- Счётчики SQLite переживают рестарт/restore. TTL comments 60 с, AI 24 ч; глобальные квоты ограничивают число строк, просроченные записи удаляются при следующем запросе. Хранятся SHA-256 IP, без исходного адреса; это технические данные, не механизм авторизации.
- Никакого wildcard доверия XFF. Uvicorn запускается с `--no-proxy-headers`; приложение учитывает только `TRUSTED_PROXY_CIDRS`, начиная с реального TCP peer и идя справа налево. Пустая настройка игнорирует XFF; `/0` и `*` запрещены. При неизвестной топологии все посетители за одним proxy могут разделять квоту — безопасный, но строгий режим.

На Render нельзя угадывать CIDR по одному адресу или доверять заголовку от клиента. Пока нет проверки реального ingress, список пуст, публичная запись запрещена. Для публичных комментариев потребуется отдельное согласование, аутентификация/доступ и проверка ingress; текущий Blueprint их не открывает.

## AI

`GET /api/ai/status` без разрешённой конфигурации или в public mode:

```json
{"configured": false, "providers": [], "models": {}}
```

`configured=true` требует **AI_ENABLED=true + AI_ACCOUNT_VERIFIED=true + ключ выбранного провайдера**. Второй флаг — подтверждение владельца после проверки аккаунта/модели/квоты, не автоматический live healthcheck. Одного имени модели недостаточно. В этой работе реальных запросов провайдерам не выполнялось; созданы только offline/mock проверки.

`POST /api/datasets/{dataset_id}/ai/explain`, только приватный режим и встроенный синтетический dataset:

```json
{"kind":"overview","context":{"class_ids":["7A"]}}
```

```json
{"kind":"comparison","context":{"topic_id":"equations","textbook_a":"Учебник A","textbook_b":"Учебник B"}}
```

```json
{"kind":"plan","context":{"plan_id":"<saved_plan_id>"}}
```

| kind | Допустимые селекторы |
| --- | --- |
| overview | class_ids, textbook_ids, test_version (все необязательны) |
| topic | обязательный topic_id + фильтры overview |
| comparison | обязательные topic_id, textbook_a, textbook_b + class_ids/test_version |
| plan | обязательный plan_id |
| teachers / comments | Пока отключены, 503 |

Исходный context ≤30000 UTF-8 JSON байт; такой же предел для построенного сервером контекста. Неизвестные поля/несовместимые селекторы — 422. `question` ≤500 символов и пока только null/пустое значение. Загруженные datasets — 403 `AI_DEMO_ONLY`, даже если автор считает данные синтетическими: разрешён только встроенный проверенный demo.

В модель уходят выбранные числовые агрегаты существующей аналитики/снимка. Нет исходных строк, student/teacher/school ID, имён, названий, комментариев, question и metadata. Темы/классы обозначаются индексами. Клиентские показатели не принимаются за доверенные. Промпты и формулы участников не переписывались; методологический QA — Тони.

Один общий deadline **20 секунд** на всю цепочку Groq→Gemini; HTTP timeout 10 с, connect 5 с. Ответ провайдера ≤64 КиБ, текст ≤15000 символов, output budget 2048 токена. Redirects и proxy из окружения отключены, адреса провайдеров фиксированы. Ошибки 503 `AI_NOT_CONFIGURED`, 502 `AI_PROVIDER_ERROR`; тело ошибок провайдера и ключи не логируются. Значения ключей дополнительно удаляются из возвращаемого текста. Успешный AI-ответ ничего не сохраняет и не меняет учебный план.

Квота AI: **3 запроса/мин/IP, 10/мин глобально, 100/скользящие 24 часа глобально**. Одна попытка может обратиться максимум к двум провайдерам; это не гарантия бесплатности. У владельца должны быть ограничения расходов в кабинетах.
