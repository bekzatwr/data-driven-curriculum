# Дополнение к ТЗ: надёжная работа с исходными данными

Версия 0.2.0, 9 ноября 2026. Эти улучшения реализованы в серверной части Бекзата и доступны через Swagger. Основной сценарий и распределение работ из Word-ТЗ сохраняются; весь интерфейс принадлежит Дамиру. Включение новых кнопок в интерфейс команда может выполнить после базового MVP.

## 1. Паспорт полноты данных

Проблема: после успешного импорта методист ещё не знает, по каким темам отсутствуют итоговые тесты и какие результаты нельзя объединить в пары.

Решение: `/quality` возвращает сводку, разрез по темам и по классам, список тем без записей и понятные уведомления. Видны количество pre/post, пар, отсутствующих учителей и доля post с парным pre. Нулевая оценка ученика остаётся валидной оценкой; отсутствие теста не превращается в ноль.

Критерии приёмки: все темы учебного плана присутствуют; при отсутствии post доля равна null; для пары учитывается «ученик + тема», а не уникальный ученик. Отчёт использует все строки набора, включая строки после первой страницы. Данные о всех учащихся школы неизвестны, поэтому школьное покрытие не заявляется.

Ответственность: Бекзат — готовый API и тесты; Дамир — отображение при включении функции в UI. Образовательные расчёты и ограничения сравнения учебников остаются у Тони.

## 2. Перенос набора одним файлом

Проблема: на другом ноутбуке приходится вручную собирать два CSV, метаданные и заново проверять, что взяты правильные файлы.

Решение: скачать `.ddc.json`, открыть на другом экземпляре приложения, проверить preview и сохранить. Пакет содержит метаданные, учебный план, все результаты, версию формата и SHA-256. Сервер проверяет и контрольную сумму, и правила самих данных.

Критерии приёмки: перенос сохраняет значения; изменение данных без обновления суммы отклоняется; некорректные данные отклоняются даже с пересчитанной суммой; повтор не создаёт дубль. На новом сервере назначается новый ID. Пакет не переносит рассчитанные планы и не может назначить себе доверенный тип источника `demo`.

Ответственность: Бекзат — готовые экспорт/валидация/импорт и схема JSON; Дамир — кнопки и показ preview. JSON-пакет не заменяет будущий CSV-экспорт отчёта Айданы.

## 3. Восстановление после сбоя ноутбука

Проблема: обычное копирование файла SQLite при работающем сервере может пропустить данные из WAL.

Решение: оператор запускает локальную команду резервного копирования. SQLite создаёт согласованную копию, после чего выполняются проверки целостности и внешних ключей. Восстановление выполняется в новый путь; существующая база не перезаписывается.

Критерии приёмки: копия содержит последние подтверждённые данные, таблицы планов и проверки P1; новый сервер читает восстановленный набор; повторная команда с тем же выходным именем завершается отказом и оставляет файл неизменным.

Ответственность: полностью Бекзат. В веб-интерфейсе и публичном API команды резервного копирования нет.

## 4. Согласование интерфейса с сервером

`GET /api/capabilities` сообщает версию, режим, лимиты и доступность загрузки/переноса. Дамир может скрыть недоступные действия и показать действительные ограничения. OpenAPI и примеры ответов формируются из приложения и проверяются в CI, чтобы документация оставалась синхронизирована с кодом.

Это законченные улучшения инфраструктуры данных. Полная демонстрация «импорт → аналитика → план → отчёт» требует последующего подключения модулей остальных участников.
